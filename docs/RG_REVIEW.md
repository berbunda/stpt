# Tier RG scenario review

2026-11-25. All 41 PG acceptance scenarios were reviewed against program **0.5.0-1**, protocol draft-61. This supersedes the 0.5.0-0 implementation walkthrough. Native executables, authenticated Server tests, QUIC fault peers, controlled DNS answer sets and state/grammar inspection supply the evidence below. A reviewed scenario is not a claim that every possible scheduler ordering or operating-system configuration was tested.

## Findings and fixes

1. **Cancelled early remote flow contacted the Client target.** The receiver waited only for Pending to become Active. A reset already received on that flow could lose a later select race to connect. A regression confirmed actual target contact before the fix. Pending/connect/reply phases now prioritize cancellation and inspect the peer direction with a cancel-safe single-byte read before networking.
2. **Account quota identity could disappear while native work retained permits.** Owned semaphore permits kept the old semaphores but not the Account Budget object referenced by the weak registry. A new Connection could obtain a fresh budget. A regression failed while retaining the native lease and dropping State. Reservations now retain the Account Budget itself through native completion/reaping.
3. **Client opening timeout sent FIN instead of TIMEOUT.** A `?` returned before reset/stop signalling. The regression observed a normal end before the fix. Opening now has one absolute deadline including stream credit; expiry resets/stops only that Channel with TIMEOUT, leaving Connection alive.
4. **Blocked reply did not observe cancellation.** A zero receive-window fault peer reproduced a failed READY write remaining blocked after rule FIN. Successful/failed READY and CONNECTED writes now observe cancellation independently of write readiness and remain deadline-bounded. DATA loops prioritize revocation and recheck authority before partial writes.
5. **Foreground forwarding omitted route monitoring.** The CLI did not run the existing route watcher used by terminal and file commands. It now keeps that watcher active, without automatic reconnect. A regression drives the same foreground runner, triggers an actual endpoint rebind and preserves a live TCP flow on both primary platforms. This omission was found by code review; the four preceding defects have saved pre-fix failing logs.

Additional validation: disallowed target ports are refused before DNS; a single optional DNS root dot is normalized but multiple trailing dots are rejected. Controlled DNS answers use the same connector as real resolution, so every numeric candidate/port and every new flow is checked. Native lookup work retains admission through actual completion; invalidated queued lookups cannot start another operation.

## Final validation

- Windows 11: full suite **339 passed**, two ignored; the RG default-timer idle test passed separately for 61 seconds. The remaining skip is the existing manual large-file test. Clippy all targets with warnings denied passed.
- Ubuntu Linux, kernel 7.0.0-44-generic, isolated Rust 1.100.0: full suite **382 passed**, ten ignored. The RG idle test and the root-only foreign-Account test passed separately. The eight remaining skips are existing non-RG privileged process, long reconnect/FUSE and large-file checks. Clippy all targets with warnings denied passed.
- Native CLI tests on both platforms exercise local/remote/SOCKS, binary and empty input, half-close, IPv6, Server-side localhost resolution, ingress/name denial, default-disabled configuration, SOCKS refusal mappings and early payload isolation.
- Cross-platform Windows Client and Linux Server passed local, dynamic/domain SOCKS and remote forwarding, each transferring 200000 bytes with TCP half-close and independently matched SHA-256 `e24bc62381f1224fbbb74688663f8f9743b9680b193edd666835e97b06e730eb`. Direct host-to-VM UDP did not answer. Cross tests therefore preserve complete UDP datagrams through a temporary SSH relay, retaining end-to-end STPT QUIC/TLS. They prove endpoint interoperability, not direct-path reachability. Fresh disposable keys were used; no personal key was inspected and no firewall or route was changed.
- Exact global and Account limits are tested through controlled reservations; this does not claim 2048 simultaneously open native sockets. DNS answer changes are injected at the resolver/connector boundary, not through an authoritative DNS infrastructure attack. System resolver/NSS work can outlive a cancelled protocol operation, but retains native and Account admission until completion and cannot dispatch a later connect after invalidation.

## Fixtures, scope and cleanup

Tests use loopback sockets and synthetic identities. A Linux rebind assertion was corrected to observe a refused new connection after listener removal: TCP TIME_WAIT can retain a closed accepted tuple and is not evidence of a live listener. The trickle fixture keeps its send direction open until timeout instead of accidentally sending FIN at eight seconds. A separate existing terminal-test assumption was reproduced with deliberately queued output: the detach helper now drains legal DATA/STDERR while still rejecting TERMINAL_EXIT. Terminal runtime semantics were not changed. Native bind collision/reuse behavior was checked against [Microsoft Winsock guidance](https://learn.microsoft.com/en-us/windows/win32/winsock/using-so-reuseaddr-and-so-exclusiveaddruse); the Windows reuse regression passes without adding a socket-option change.

Runtime timings retain the production 10-second opening/handshake and 60-second stalled-progress defaults. Short injected clocks make fault transitions deterministic; real default opening and idle deadlines are also exercised. The CLI still opens one rule per command. Server policy remains immutable until restart; Windows remains limited to its current Account/token. UDP forwarding, SOCKS BIND/authentication extensions, Session-persistent listeners, automatic reconnect and later Tiers were not added.

The program repository's ignored target directory contains the failing regressions, final Windows logs, Linux log archive and cross-test logs. All task-owned VM test executables are stopped before removing its exact temporary validation directory. The existing global toolchain, projects, disk layout and network settings are preserved. The original 0.5.0-0 review figures were Windows 308 and Linux 350 plus its root test; they describe the earlier milestone, not the final evidence above.
